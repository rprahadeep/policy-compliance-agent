AI-POWERED POLICY COMPLIANCE INTELLIGENCE ASSISTANT
ARCHITECTURE AND WORKFLOW OVERVIEW

1. PROJECT PURPOSE

This project is a policy compliance assistant that answers employee compliance questions using official policy PDF documents.

The user asks a natural-language question, the system retrieves relevant policy evidence, a LangGraph multi-agent workflow reasons over that evidence, and the frontend shows a clear compliance decision with risk, recommendations, citations, and agent trace.


2. HIGH-LEVEL ARCHITECTURE

The system has three main layers:

Frontend
- React + Vite single-page app.
- Lets the user ask a compliance question, add scenario context, choose a policy category, sync policy documents, and inspect the final answer.

Backend
- FastAPI service.
- Handles document ingestion, retrieval, agent orchestration, analytics, and API responses.

Knowledge Layer
- Policy PDFs are stored locally in backend/data/policies.
- OpenAI embeddings convert policy chunks into vectors.
- Pinecone stores and searches vectors.
- A local JSONL chunk cache supports keyword search and citation metadata.


3. DATA SOURCES

The assistant uses policy PDF files stored in:

backend/data/policies/

Conceptually, each PDF is treated as an authoritative source. During ingestion, the backend extracts text from the PDFs, splits the text into smaller policy chunks, attaches metadata, embeds each chunk, and stores it for retrieval.


4. INGESTION FLOW

Ingestion happens when the user clicks "Sync policy index" or calls the ingest API.

Flow:

1. FastAPI scans the policy PDF folder.
2. PDF text is extracted page by page.
3. Text is cleaned and normalized.
4. Policy metadata is inferred, such as policy name, category, page, section, and framework.
5. Text is split into overlapping chunks so each retrieved passage has enough context.
6. Each chunk is embedded using the OpenAI embedding model.
7. Embeddings and metadata are stored in Pinecone.
8. Chunk records are also saved locally for keyword retrieval and citation display.

Purpose:

The ingestion flow converts raw policy PDFs into searchable policy knowledge.


5. QUERY FLOW

The query flow starts when the user submits a compliance question from the frontend.

Flow:

1. Frontend sends the question, optional employee context, and optional policy filter to FastAPI.
2. Backend validates the question with guardrails.
3. The retrieval layer searches for relevant policy chunks.
4. Retrieved chunks are passed into the LangGraph agent workflow.
5. Agents interpret policy evidence, check compliance, assess risk, and recommend actions.
6. Backend formats the final answer, citations, context precision, risk score, and agent trace.
7. Frontend displays the decision brief, evidence panel, recommendations, and analytics.

Purpose:

The query flow turns a user scenario into a citation-grounded compliance decision.


6. RETRIEVAL METHOD

The project uses hybrid retrieval.

Semantic Retrieval
- The user question is embedded.
- Pinecone finds policy chunks with similar meaning.
- Useful when the user asks in natural language.

Keyword Retrieval
- Local chunks are searched using keyword overlap.
- Useful for exact compliance terms such as "multi-factor authentication", "authorization", "incident", or "access".

Reranking
- Semantic and keyword results are merged.
- Results are scored and ordered.
- The best chunks are passed to the agents as policy context.

Why hybrid retrieval is used:

Compliance language often depends on exact terms, but users usually ask questions conversationally. Hybrid retrieval handles both.


7. LANGGRAPH AGENT WORKFLOW

The backend uses LangGraph to make the reasoning workflow explicit and inspectable.

Main graph path:

validate_input
  -> retrieve_policy
  -> interpret_policy
  -> check_compliance
  -> assess_risk
  -> recommend_actions
  -> compose_answer
  -> END

Agent roles:

Input Guardrail Agent
- Checks whether the user question is valid, policy-related, and not a prompt-bypass attempt.

Policy Retrieval Agent
- Retrieves relevant policy chunks using hybrid retrieval.

Policy Interpretation Agent
- Explains what the retrieved policy evidence means in plain language.

Compliance Checker Agent
- Decides whether the requested action is compliant, non-compliant, needs review, or unclear.

Risk Assessment Agent
- Scores the severity of the scenario from 0 to 100.
- Assigns a risk band: low, medium, high, or critical.
- Decides whether escalation is needed.

Recommendation Agent
- Suggests compliant next steps, safer alternatives, or escalation paths.

Final Response Agent
- Produces the user-facing answer grounded in retrieved policy citations.


8. RESPONSE SHOWN TO THE USER

The frontend presents:

- Compliance status
- Risk score and risk level
- Final answer
- Recommended actions
- Risk rationale
- Context precision
- Policy citations
- Agent trace
- Basic analytics

Context precision means:

The share of retrieved policy passages that appear relevant enough to support the answer. Higher context precision means the model received cleaner policy context with less irrelevant noise.

Risk score means:

The estimated severity of the compliance issue from 0 to 100. Higher means greater policy impact or escalation concern.


9. METHODS USED

RAG
- The system retrieves policy evidence before generating an answer.

PDF Processing
- Policy PDFs are parsed and chunked into smaller searchable passages.

Embeddings
- Policy chunks and user questions are converted into vectors.

Vector Search
- Pinecone finds semantically similar policy chunks.

Keyword Search
- Local chunk text is searched for exact term matches.

Hybrid Retrieval
- Semantic and keyword results are combined for better policy search quality.

LangGraph Agents
- The reasoning process is split into clear agent steps.

Guardrails
- User input is checked before retrieval and generation.

Citations
- Answers include source policy evidence so the user can verify the result.

Analytics
- Query history is summarized for dashboard metrics.

LangSmith Tracing
- When enabled, LangSmith records LangChain and LangGraph execution traces for debugging and observability.


10. CONCEPTUAL END-TO-END SUMMARY

1. Policy PDFs are added to the backend.
2. The backend extracts and chunks policy text.
3. Chunks are embedded and stored in Pinecone.
4. The user asks a compliance question in the React UI.
5. FastAPI receives the request.
6. Guardrails validate the input.
7. Hybrid retrieval finds relevant policy evidence.
8. LangGraph agents reason over the evidence.
9. The backend returns a grounded answer with risk, recommendations, citations, and trace.
10. The frontend displays the result in a decision-focused interface.


11. FINAL DESCRIPTION

This project is a full-stack RAG and multi-agent compliance assistant. It transforms policy PDFs into searchable knowledge, retrieves relevant evidence for user questions, applies a LangGraph compliance reasoning workflow, and returns citation-grounded answers through a modern React frontend.
